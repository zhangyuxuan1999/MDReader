## 5. Behavioural clarifications
- `EditorApi.onChanges` handlers run synchronously inside CM's updateListener; they must be cheap (post a message) — never touch DOM there.
- `PreviewOptions.request(ids)` and `viewport()` are called by the preview from rAF callbacks; the worker client coalesces/throttles them.
- `StructureMsg.blocks` is transferred; the preview may keep the array (the worker never reuses it).
- `nav:gotoLine` is handled by scrollSync (SPEC §6) which moves BOTH panes; the TOC/preview only emit the event.
- `doc:cursor` is emitted by App from `editor.onCursor` (E4 wires it), not by the editor module directly.
- `file:dirty`, `mode:changed`, `theme:changed` are emitted by App. `toast` may be emitted by anyone; App renders it.
- Line numbers are 1-based everywhere; `data-l` on preview elements is 0-based relative to the block's start line.
- Draft restore prompt, unsaved-guard and all dialogs are App's (E4). Preview never prompts.
- Editor `setDoc` must reset undo history and emit `onChanges`? NO: `setDoc` does not call `onChanges`; App calls `worker.setDoc` itself with the returned version.
- Empty document: worker sends a `structure` with 0 blocks; preview renders nothing; stats all zero, readingMinutes 0.

## 7. Structure deltas (lead, round 3)
- New `FromWorker` message `StructureDeltaMsg` (`type:'structureDelta'`, see src/shared/types.ts): after every `edit` flush the worker sends ONE delta `{index, removed, inserted: Int32Array, lineDelta, changed, lineCount, stats, outlineVersion}` instead of a full `structure`. `inserted` is transferred. Blocks after the replaced range keep id/kind/lineCount and shift `startLine` by `lineDelta`. A full `structure` is still sent for `setDoc`, after a worker restart, and whenever the worker cannot express an update as a single contiguous replacement (it may always fall back to a full `structure`).
- Worker side: `edit` messages are queued and flushed in one task (MessageChannel), so a burst of queued edits is applied before any resegmentation; inside a transaction the ascending original-coordinate changes are applied in ONE pass over the affected line range (no per-change splice of `lines`), then `resegmentWindow` runs once over the union window. Cost is O(affected text + changes), never O(changes × lines-in-block).
- Preview side: `applyStructureDelta` splices persistent growable typed arrays (ids/starts/lines/kinds/heights, capacity grown ×1.5) in place with `copyWithin`; `tops` is recomputed in place into a persistent buffer. No full-document allocation per keystroke on either side. `applyStructure` (full) remains the reset path and must still work.
- Shell side: `createWorkerClient` forwards `structureDelta` to `handlers.onStructureDelta`; App applies it to the preview, updates stats/progress exactly like a full structure.
- `isFromWorker` (src/shared/protocol.ts) already accepts `structureDelta`.

## 8. Resync (lead, final round)
- `ToWorker` `{ type: 'resync' }`: the worker answers with a full `structure` (and the outline if its version changed) for the current version. `PreviewOptions.resync()` is called by the preview when it cannot apply a `structureDelta` (bounds mismatch, unknown state); App forwards it to `WorkerClientApi.resync()` (coalesced per frame). Never used on the hot path.
- Worker side (`src/worker/core.ts`): `resync` **drains the queued `edit` transactions first**, so the answer describes the version the client has already sent (their `structureDelta`s go out ahead of the full `structure`; a desynced preview ignores them and the `structure` then re-seeds it). `changed` carries the still-dirty ids — exactly the blocks whose HTML the preview has not been given for this version — so the preview re-requests them. The outline is repeated only when its version differs from the last one actually posted. Like `viewport` / `need`, a resync is answered with an `idle` even when there is nothing left to render: a `structure` puts App back into "rendering", and `waitIdle()` / the 「渲染中」 indicator must be released again.
- Client side (`src/app/workerClient.ts`): `resync()` is coalesced per animation frame, arms the request watchdog like any other outgoing request, and is dropped by a restart (a restart sends a full `structure` by itself).
- Restart replay order is fixed and unthrottled: `init` → `setOptions` (accumulated) → `setDoc` (from `onRestart()`) → `viewport` (the last window the PREVIEW asked for, recorded when the request arrives, not when the 100 ms throttle lets it out) → `draft('enable')`. The preview sends a window only when its first/last line changes, so a window still sitting in the throttle when the worker dies would otherwise be lost and the new worker would auto-push the window the user left (the s07b restart flake).

## 9. Focus line (lead, 2026-09-18)
The line the user is "on" in one pane is tinted there and mirrored, with the same background, in the other.
Subtle by design (no border, no bright colour), and it never scrolls, never moves the caret, never steals focus.
- **Token** `--mdr-focus-line` (tokens.css): light `rgba(191, 87, 0, 0.09)`, dark `rgba(255, 190, 120, 0.11)`.
  `--mdr-active-line` is `var(--mdr-focus-line)`, so CodeMirror's caret line and the preview's focus line are
  the same colour by construction.
- **Bus** `focus:line {line, source:'editor'|'preview'}` (src/shared/types.ts). App wires it in
  `src/app/focusLine.ts`: `doc:cursor` → emit with `source:'editor'` when `editor.hasFocus()` or `e.typing`
  (a programmatic cursor move is not the user); `source:'editor'` → `preview.setFocusLine(line)`;
  `source:'preview'` → `editor.setPeerLine(line)`. `openFile` (every load / open / new) calls `reset()`, which
  clears both and drops the one cursor event `setDoc` schedules — nothing is tinted in the preview until the
  user interacts. Mode switches keep the state (the hidden pane keeps its class): `applyMode`'s programmatic
  `editor.focus()` would make the editor drop the mirror, so it is followed by `focusLine.reassert()`, which
  re-applies the last `focus:line`. Only a focus the USER gives the editor clears the mirror.
- **Editor** (`src/editor/peerLine.ts`): `highlightActiveLine` keeps tinting the caret line. `setPeerLine`
  dispatches a `StateEffect` into a `StateField` holding at most one `Decoration.line({class:'cm-peerLine'})`;
  out-of-range lines clamp, NaN/null clear. While a peer line is set, `EditorView.editorAttributes` adds
  `mdr-peer-active` to `view.dom` and editor.css makes `.cm-activeLine` / `.cm-activeLineGutter` transparent —
  exactly ONE tinted line per pane. The field clears itself on any transaction that sets the selection and on
  `focusin` of the content DOM. The class goes through `editorAttributes`, not `classList`: CodeMirror rewrites
  the whole `class` attribute of `view.dom` whenever it updates its own attributes (e.g. losing `cm-focused`,
  which is exactly what a click in the preview causes).
- **Preview** (`setFocusLine`, `src/preview/focusLine.ts`): `blockAtLine(line)` → that block's `section.md-block`;
  inside it, `pickFocusElement` takes the element with the largest `data-l` ≤ `line − startLine`, deepest first
  when several nest with the same value, falling back to the wrapper. Exactly one element carries `.is-focus`
  (`.mdr-preview__body .is-focus` in preview.css: background + a 4 px box-shadow of the same colour). The focus
  line is remembered and re-applied (rAF-coalesced, one block's subtree only, no layout reads) when that block
  mounts, re-renders, is evicted and remounted, or when a structure/delta moves the line.
  A fenced block carries a single `data-l` (the fence's opening line), so any line inside it tints the whole
  `<pre>` and mirrors back to that opening line; per-line precision inside fences is out of scope. Likewise
  `li` / `blockquote` / `table` tint as a whole.
- **Interactions** (`src/preview/interactions.ts`): a primary click without Ctrl/Meta inside a `[data-l]` tints
  and emits (Alt+click keeps its `nav:gotoLine` behaviour and also tints); a non-collapsed `selectionchange`
  whose anchor is inside the preview focuses the anchor's line, rAF-coalesced and skipped when unchanged.
- **Verification**: `bench/verify/focus-line.mjs` (`MDR_BASE`, dev server on :5241 by default), unit tests in
  `test/focusLine.test.ts`.

## 10a. Desktop fix round 2 (fixer, 2026-09-21) — deltas to §10
Findings from the desktop verification round, fixed at the root. `src/shared/**` is untouched.
- **File fidelity** (`electron/fileIO.mjs`, new): the shell remembers encoding / BOM / line ending /
  mtime per RESOLVED path and restores them on write. A file is decoded with its real encoding
  (strict UTF-8, then BOM'd UTF-16, then GBK / Big5 / Shift_JIS / EUC-KR / windows-1252) and written
  back in it — `readFile(p,'utf8')` turned every stray byte into U+FFFD and the next ⌘S persisted the
  damage. Undecodable bytes are refused (EIO) instead of guessed. A CRLF file stays CRLF even though
  CodeMirror's document is always LF. Writes follow symlinks (`realpath`) and, for `nlink > 1`, go in
  place so hard links stay joined (documented loss of atomicity for that case only). A file another
  program changed since it was read is refused once with `CONFLICT_MESSAGE`; the shell then adopts the
  new mtime, so the renderer's 覆盖保存 is simply the same write again.
  `NativeFileInfo` gains a non-contractual extra field `encoding` (readers that ignore it are
  unaffected); the renderer keeps it in a side map (`src/files/nativeBackend.ts`), never in `OpenedFile`.
- **CSP**: every `app://` response carries `CSP_PACKAGED` (`electron/protocol.mjs`), and the dev server
  gets `CSP_DEV` through `onHeadersReceived`. A document cannot reach the network at all; the renderer
  toasts once per document when something is blocked. `index.html` therefore has no inline script —
  the pre-paint theme bootstrap lives in `public/theme-boot.js`.
- **撤销 / 重做 are custom menu items, not roles** (§10 said roles): Chromium's Redo editor command
  cannot drive CodeMirror 6's history, so the item did nothing. They are shell-only ids
  (`EDIT_UNDO` / `EDIT_REDO` in `src/app/native.ts`, beside `app.closeRequested`, because `CommandId`
  is frozen) that the renderer answers with `@codemirror/commands` undo/redo. cut/copy/paste/selectAll
  stay roles. `registerAccelerator:false` as for every other custom item.
- **Editor-scope shortcuts and menu items work from any pane**: `installShortcuts`' `find` hook became
  the general `editorCommand(id)` hook, and shell command ids route through App's `runEditorCommand`
  (switch out of 预览, focus the editor, run).
- **Drafts**: a draft offer is scoped to the document on screen (dismissed when another opens) and the
  scratch buffer's offer waits for the shell's launch document before appearing. `restoreDraft` on a
  foreign draft says so instead of doing nothing.
- **Theme**: 视图 → 切换主题 cycles 跟随系统 → explicit → 跟随系统 (`nextThemePref` in `src/app/App.ts`).
- **Install**: `scripts/install-app.mjs` unregisters AND deletes `release/mac-arm64/MDReader.app`
  before `lsregister -f -R` on `/Applications`, so exactly one bundle claims `com.zyx.mdreader`
  (verified by reading `lsregister -dump` back). `-R` is load-bearing for .mdown/.mkd/.mkdn.
- **Open-file after the window was closed (hotfix, 2026-11-20)**: closing the window (red button / ⌘W;
  the app stays in the Dock) left the open queue in live mode, so the next double-click's path went to
  `deliver` with no window and was dropped, and the new window showed an empty 未命名.md. Now:
  `createOpenFileQueue(deliver)` requires `deliver` to return `true` only when a live window's
  webContents took the path; on anything else the queue goes back to buffering and keeps the path
  (deduplicated, in order; a flush interrupted mid-way keeps the rest). `reset()` = "consumer gone or
  new", pending paths survive. `electron/main.mjs` resets the queue when the window's `close` goes
  through and on `closed`; `open-file`, `second-instance` and `activate` all go through
  `ensureWindow()`: queue first, then create the one window if none is live (a window still closing
  defers the new one to its `closed` event — never two windows), else focus. Nothing creates a window
  before the whenReady setup (`shellReady`); paths queued earlier reach the first window. Several
  paths for one new window are delivered in order to that renderer (its dirty guard decides; clean →
  the last is shown). E2E: `bench/electron/open-lifecycle.mjs` (`MDR_EXE=` packaged or
  `MDR_APP_DIR=` unpacked), unit: `test/electron.openQueue.test.ts`.
- **Follow-up hotfix (2026-11-20), main process only** — e2e checks (10)–(18) of `open-lifecycle.mjs`,
  unit tests in `test/electron.fileIO.test.ts`:
  - *Renderer gone*: `render-process-gone` resets the open queue, forgets the dead renderer's

## 11. In-preview editing (lead, 2026-09-26)
Contracts (src/shared/types.ts): `PreviewSourceAccess` (`PreviewOptions.source`, wired by App to CodeMirror), `BlockInfo`, `PreviewApi.blockOfElement / elementOfBlock / setPreviewEditable / isPreviewEditable / endEditSession`, `CommandId 'view.togglePreviewEdit'` (⌘⇧E, toolbar pencil-on-page toggle, persisted in `LS_PREVIEW_EDIT`, default ON), bus `previewEdit:changed` / `previewEdit:session`.
- Module: `src/preview/inlineEdit.ts` (owned by the preview module) + `src/preview/serialize.ts` (block DOM → Markdown). App only wires `source`, the command, the toolbar state and the status hint.
- Session model: ONE block at a time. When editable is on, `mousedown` inside an editable `section.md-block` marks it `contenteditable=true` + `.is-editing` and the browser places the caret (nothing is written until the DOM changes). Editable kinds: Prose, Heading, List, Quote, Code, Table, Math. NOT editable (toast 「此块请在源码中编辑」): Html, Hr, PLAIN fallbacks, `.md-error`. Every DOM change (`input`, but never during IME composition — `compositionstart` … `compositionend`) serializes the block to Markdown and, when the result differs from the session's baseline (the serialization of the block's DOM at session start), calls `source.replace(startLine, lineCount, text + originalTrailingBlankLines)`; the block's original trailing blank lines are preserved verbatim. Serialization runs at most once per animation frame.
- While a session is active the preview holds back worker HTML for that id (applies it when the session ends), never evicts the block, keeps structure/height updates flowing, and tracks the block's id/startLine/lineCount through structure deltas. If a write makes the block split into several blocks (Enter creates a paragraph; an empty list item leaves the list), the session ends and, once the new HTML mounts, a new session starts on the block containing the caret with the caret at the mapped position (start of the new block for a split).
- Keys inside a session: Enter = new paragraph (Prose/Heading; in a Heading the new block is a paragraph) / new item (List, native) / newline (Code) / no-op (Table; Tab and Shift+Tab move between cells); Shift+Enter = hard line break, serialized as two trailing spaces + newline; Esc = end session (caret stays visually, block re-renders from the worker); ⌘B/⌘I/⌘E/⌘K = strong/em/inline code/link (⌘K prompts for the URL via a small inline input); Tab/Shift+Tab in a list = indent/outdent (native or manual); ⌘Z/⇧⌘Z while editing = the browser's own undo of the contenteditable (source follows through the input event). Paste = plain text (`insertText`), newlines become `<br>`. Clicking a link while editing places the caret (⌘-click opens); checkboxes still toggle. The focus-line tint keeps working. Global shortcuts (⌘S, ⌘/, ⌘⇧P …) still work; ⌘S commits first.
- Serializer (`serialize.ts`): built on `turndown` + `turndown-plugin-gfm` (allowed new deps, + @types/turndown) with options `{headingStyle:'atx', bulletListMarker:'-', codeBlockStyle:'fenced', emDelimiter:'*', strongDelimiter:'**', hr:'---'}` and custom rules for: `.katex` (read `annotation[encoding="application/x-tex"]` → `$…$` inline, `$$\n…\n$$` display), `pre.md-code[data-lang]` → fenced with the language (textContent, hljs spans dropped), task list items (`- [ ] ` / `- [x] `), `<br>` → `  \n`, `del` → `~~`, images `![alt](src "title")`, headings by level, tables with alignment (escape `|` in cells), nested lists with 2-space indent (ordered lists renumbered 1., 2., …), blockquotes (`> ` per line, nested), `.md-plain__note` and other UI-only elements ignored, `data-l`/`class` attributes ignored. Escaping: turndown's default plus `$` when the text is not inside math. - **Stage-2 decisions (lead, 2026-11-20)** — after the adversarial verification of the 0.2.0 candidate (docs/FINDINGS-0.2.0-r1.md: 45 confirmed findings in 39 groups G1–G39). Binding for fix round 2; where they contradict an earlier bullet of this section, these win.
  - **INV — the three invariants of in-preview editing.** (1) *Source equals screen*: one frame after the last input the document (CodeMirror) is what the preview shows, including a block the user emptied; no reader of the document (⌘S, export, drafts, the close question, the editor pane) can see older text. (2) *Only what was typed changes*: an edit changes only the edited block's lines, and inside the block only what the user changed; where the serializer cannot prove that a compact spelling renders the same, it writes the general spelling or the block is refused (此块请在源码中编辑). (3) *The document does not steer the app*: nothing a document can carry (attributes, classes, characters, links) is read as one of the app's own markers or moves the app window.
  - **U7 — pointer and selection (G15; replaces "a primary mousedown … makes that wrapper contenteditable").** A session starts when the primary button is RELEASED: press and release in the same editable block, no modifier key, and the resulting selection collapsed or inside that block; the caret (or that selection) is where the browser put it. A drag that crosses a block boundary selects text exactly as with 预览可编辑 off and starts no session. A drag that starts in the block being edited and leaves it ends the session (pending text written) and the selection extends over the other blocks; if that proves infeasible the selection may stay inside the block, and the fixer says so. ⌘A in a session selects the block's content; ⌘A again, when that content is already fully selected, ends the session and selects the whole preview. Shift-click, ⌥ / ⌘ / Ctrl-click, checkboxes, links and math keep their rules. A pointer gesture is interpreted against what the user saw when the button went down: a session end caused by the press does not move content before the release (DOM removal or re-mount caused by that end waits until after the click), and what the click then does (start a session, toggle a task) is resolved against a structure that describes the current source; while a write is still on its way through the worker the click waits for it (bounded, about 300 ms) instead of being dropped or applied to stale line numbers.
  - **U8 — paste size (G6).** A paste that would make the block's source longer than `MAX_EDIT_CHARS` (60 000) is refused: nothing is inserted and a toast says 「粘贴的内容太长，请在源码编辑器中粘贴」. A paste below the limit is one DOM insertion, and `serializeBlock` is linear in the block's size. Budgets (this machine, quiet): pasting 55 000 characters, as one line and as 1 000 lines, blocks the page ≤ 500 ms; the flush of the next keystroke ≤ 100 ms.
  - **U9 — an emptied block (G7; replaces "the deletion is written when the session ends").** When the block being edited has no content left, the next frame flush writes the deletion: the block's lines and its own trailing blank lines leave the source (no extra blank line stays behind), the document is dirty, the editor pane shows it. The session stays alive on the emptied element: text typed next is written as a new block at the same place and the session continues on it through the ordinary resume; leaving the emptied element writes nothing more. ⌘Z brings the block back (U1). `flush()` and `end()` never leave a deletion pending.
  - **U10 — trust boundary (G1).** (a) `HTML_FLAG_RESERVED` (src/shared/types.ts, the next free bit of the per-block HTML flags): the worker sets it when any raw-HTML token of the block (html_inline / html_block) carries a name the app reserves: an attribute named `data-l`, `data-lang`, `data-md…` or `data-mdr…`, or a class token starting with `md-` or `mdr-`; tested case-insensitively on the token text with numeric character references decoded. (b) createPreview puts the attribute `data-mdr-x` on the block wrapper (`section.md-block`) at every mount of a block whose flags have the bit, and removes it otherwise. (c) `unsupportedReason()` returns a reason for a wrapper that carries `data-mdr-x`: such a block is refused and never serialized. (d) The sanitizer removes every attribute named `data-md`, `data-md-block` or `data-mdr-*` from block HTML (the worker emits none of them). (e) The serializer never copies an attribute value into Markdown structure unchecked: a link destination, a title or a code language that contains a line break or another control character is written in a form that stays on its line and renders the same, or the block is refused; `data-md` placeholders are honoured only when `prepare()` created them in the same call.
  - **U11 — a link whose text is its URL (G2).** Bare URL only when linkify would start at its first character, stop at its last, and show the same text; `<url>` only when it is a valid CommonMark autolink that shows the same text; otherwise the inline form `[text](destination)`. The same proof-or-general rule holds wherever the serializer chooses between a compact and a general spelling.
