- **[medium] P13 misses the 450 MB renderer target on huge.md: 568 MB after load, 810 MB peak, 580 MB settled after 30 s + forced GC**
  - file: src/preview/createPreview.ts:23

Note the fixture ambiguity: SPEC §11 sizes its 'large' document at 10 MB / ~100k lines, which matches huge.md's byte size, so huge.md is the fixture the 450 MB number was written for.

- **[medium] The P5 "main-thread work per keystroke" gate in bench/perf.spec.ts can never report a value below ~20 ms, so it prints 0.0 ms and cannot fail**
  - file: bench/perf.spec.ts:144
  - expected: SPEC §11: "CI fails on any target miss or > 20 % regression vs bench/baseline.json", with P5 on every PR. The P5 gate should distinguish 2 ms/keystroke from 19 ms/keystroke and fail at 5 ms.
  - actual: The gate reports exactly 0.0 ms for both p95 and max and passes unconditionally. A direct measurement of the same scenario disagrees by an order of magnitude: MDR_BASE=http://localhost:5221 node bench/verify/p5-clean.mjs large 200 100 split gives 23.6 ms p95 / 27.7 ms max of idle-baseline-adjusted main-thread busy per keystroke, with the longest single main-thread turn at 19.4 ms p95. A regression that doubled per-keystroke work to, say, 12 ms would still print 0.0 ms and pass CI.
  - repro: npm run perf (manages :5199 itself). Output row: `P5 main/keystroke p95 | 0.0 ms | < 5` and `P5 main/keystroke max | 0.0 ms | < 10`. The value comes from `perKey.push(Math.max(frameExcess(typed.frames, from, to), lt))` where `lt` sums only `longtask` PerformanceObserver entries (emitted only at ≥ 50 ms) and `frameExcess` (bench/perf.spec.ts:72) sums only rAF gaps *beyond a 20 ms threshold*. Both terms are 0 for any per-keystroke cost under 20 ms, so the metric is identically 0 across the entire range the < 5 ms / < 10 ms targets are meant to police.
  - fix: Replace the longtask/frameExcess estimator with a direct main-thread occupancy measure. The repo already has one that works: the MessageChannel event-loop monitor in bench/verify/common.mjs (`window.__probeMonitor`, PROBE_INIT) records every turn gap > 2 ms; subtract an idle baseline measured with the same monitor immediately before typing, exactly as bench/verify/p5-clean.mjs does. Alternatively adopt the trace-based marginal measurement in bench/verify/p5-marginal.mjs (types at several inter-key delays and divides total renderer busy time by key count) so the fixed per-frame rendering cost is separated from the marginal per-key cost. Either way, also assert the longest single main-thread task while typing, which is the number that actually stays meaningful at 60 wpm.
